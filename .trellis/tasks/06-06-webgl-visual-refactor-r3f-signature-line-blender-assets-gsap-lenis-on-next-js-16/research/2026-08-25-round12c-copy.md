**The cap algebra, done independently.** For `h ≤ bandH`: `p0 = b0`, `p1 = b1 − h`, so `yc = (headerH + ih − h)/2` = the exact midpoint of `y ∈ [headerH − h, ih]`. Hence `dy = yc − y` sweeps `±D`, `D = (ih + h − headerH)/2`, and `xSlow = R·α_read·dy` is antisymmetric (`traverse-rate.ts:187-189`). `capped = capPx·tanh(xSlow/capPx)` therefore sweeps `±capPx·tanh(...)`, peak-to-peak **`2·capPx·tanh(...)`**. With `capPx = blk.h`, sup = `2h`; per line that is `2·lineHeight/fontSize` = **3.00 em/line at leading 1.5** against §B2b's authored 1.5. With `capPx = blk.h/2`, sup = `h` ⇒ per line = `lineHeight/fontSize` = **exactly the block's own CSS leading**, at every viewport *and every angle* (tanh saturates). The task's diagnosis is exactly right.

`gHat` is antisymmetric too (`±fyc`), and `D − fyc = h/2 + m`, so the fast component's excursion is `2R(α_edge−α_read)(h/2+m)` and is **constant across the plateau** (`F' = V̂ = 1` there) — which is why "plateau drift" is purely the slow term, and why capping the slow term costs the swing nothing.
